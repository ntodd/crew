# Crew 0.1.1

Fixes from standing up the first real deployment: a control plane in a
Debian VM on TrueNAS SCALE, with a `linux-vm` Flatcar box beside it.
It's also the first release a control plane updates to from its
Deployment page.

## What changed

- **Jobs on a personal account's installation run.** Crew counted the
  `members` permission as missing on every installation on a personal
  account, where GitHub never grants it, and refused every job there
  (#33). Organization installations are unchanged.
- **Flatcar boxes provision with Funnel on.** A new box resolved the
  control plane's name through the uplink's DNS, got its public Funnel
  address, and waited on `/healthz` forever. The Ignition now points
  `/etc/resolv.conf` at resolved's stub, so the tailnet name resolves
  over the tailnet (#31, #34). Boxes that already enrolled don't need
  anything; a box set up on 0.1.0 that's stuck provisioning needs
  `ln -sfn ../run/systemd/resolve/stub-resolv.conf /etc/resolv.conf`,
  or a reprovision from 0.1.1.
- crew-cache's DNS listener picks another port when the one it got
  has its TCP side taken (a flaky test, mostly; #30).

## Before you install it

- Nothing to migrate, and the protocol is unchanged.
- The hardware checks in `docs/releasing.md` weren't run for this
  release either. The `linux-vm` box on TrueNAS enrolled and runs on
  0.1.0 with the resolver fix applied by hand.
