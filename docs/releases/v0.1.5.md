# Crew 0.1.5

Mac boxes keep crew-vzd running after they enroll. The Boxes page now
shows the whole fleet and says which boxes can't take jobs. Jobs whose
`completed` webhook went missing settle on their own.

## What changed

- **Enrolling no longer locks crew-vzd out.** On a Mac, crew-vzd runs as
  `_crewvm` and starts `agent/current/bin/crew-vz`. The installer makes
  `agent/` 0750 so it can, but the agent set `agent/` to 0700 when it
  enrolled. From then on launchd couldn't start crew-vzd ("Missing
  executable", exit 78), and the box reported "Firewall not verified"
  and got no VMs. A box whose crew-vzd was already running kept working
  until crew-vzd restarted. The agent now leaves an existing `agent/`
  alone. `identity.json` is still 0600.
- **The Boxes page covers the fleet.** It's full width. At the top are
  boxes online, the cores (by guest arch) and memory the online boxes
  offer job VMs, and VMs by state. Under them are vCPUs and memory
  provisioned against what's allocatable, each with a meter and a live
  chart stacked by box, over 30 minutes to 24 hours. Each box's card
  shows its CPU and memory over the range, what its VMs hold of what it
  offers, and its VMs by state and size.
- **A box that can't take jobs says so.** A box that's online but has an
  unverified firewall used to show only a green "Online". Now a callout
  at the top of the Boxes page lists every box that's offline, not
  reported, unverified, waiting for approval or quarantined, with the
  reason. Its card says what that means and where to look, and a
  "Firewall unverified" badge shows next to Online on the Boxes page,
  the dashboard and the box's page.
- **The repo list has filters:** a search on the name, state,
  visibility and "Has a priority". They're kept in the URL.
- **Stuck jobs and runs settle.** A job Crew doesn't run stayed "in
  progress" forever when its `completed` webhook went missing, and so
  did its run. The reconciler now re-checks any unfinished job with no
  event for an hour. It also re-checks a run attempt whose jobs are all
  done after 15 quiet minutes, and keeps trying every 5 minutes until
  GitHub says the run is done.

## Before you install it

- Two migrations run on start. One adds `run_attempts.checked_at` and
  partial indexes on unfinished jobs and attempts. The other indexes
  `vms.destroyed_at`. The protocol is unchanged.
- On a Mac box that shows "Firewall not verified", or that enrolled on
  0.1.4 or earlier, run
  `sudo chmod 0750 "/Library/Application Support/Crew/agent"`. 0.1.5
  doesn't change the mode of a directory that's already there.
- Jobs and runs already stuck "in progress" settle within a few
  reconciler passes after the update. Runs follow their jobs about 15
  minutes later.
- The hardware checks in `docs/releasing.md` weren't run for this
  release.
