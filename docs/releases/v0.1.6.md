# Crew 0.1.6

Jobs can install Ruby and Python with their setup actions. Mac boxes
report their cache and tell it which networks to refuse.

## What changed

- **The guest has GitHub's tool cache.** `ruby/setup-ruby` and
  `actions/setup-python` only install their prebuilt builds in
  `/opt/hostedtoolcache`, and setup-ruby failed straight away with
  `EACCES: permission denied, mkdir '/opt/hostedtoolcache'`. The image
  now has that directory, owned by `runner`, and the runner's `.env`
  sets `RUNNER_TOOL_CACHE` and `AGENT_TOOLSDIRECTORY` to it, as GitHub's
  runners do. Every setup action now installs there instead of under
  `_work/_tool`.

- **Mac caches report, and get site4.** The agent only started its cache
  reporter when `CREW_CACHE_MGMT_URL` was set, and a Mac finds its cache
  VM without it. So Mac boxes showed an empty cache on the Caches page,
  and never pushed site4 (the box's networks and egress address) to the
  cache, which therefore didn't refuse them as upstreams.

## Before you install it

- The tool cache is a guest image change: boxes pick up the 0.1.6 image
  after the update, and jobs on the old image still fail at setup-ruby.
- Mac caches start reporting, and get site4, within a minute of the
  agent's update. Their earlier traffic isn't counted.
- The protocol and the database are unchanged.
- The hardware checks in `docs/releasing.md` weren't run for this
  release.
