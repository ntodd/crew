# Crew 0.2.1

Docker-in-Docker and new Buildx container builders now use the box's registry
cache. This fixes the direct BusyBox pull that hit ECR Public's rate limit
in Foreman's firewall CI. Crew also configures nested Docker daemons started
by systemd in containers with a volume at `/var/lib/docker`.

## Upgrading

1. Back up the control-plane database. Two migrations run at startup. One
   extends the original default allowlist with `registry-1.docker.io/hexpm/elixir`,
   `quay.io/coreos/ignition-validate` and the Buildx builder image,
   `registry-1.docker.io/moby/buildkit`. The other adds the strict-mode
   setting, initially off.
2. Update the control plane, then the box agents and runner guest images.
   The nested Docker and Buildx fixes take effect for jobs using the new image.
   If you customized the allowlist, add the entries you need under
   **Admin → Caches** and enable their registry hosts.
3. To stop direct upstream fallback, enable **Admin → Caches → Registry
   fallback → Require the registry cache**. New VMs then fail a pull if the
   cache refuses it or is unavailable. Older guests cannot start strict jobs.
   The box cache can still reach upstream for cold pulls and tag refreshes.

Strict mode blocks private pulls and external pushes. A local registry at
`localhost:5000` still supports both. For Buildx container builders, the
daemon's HTTP(S) access is limited to the cache and loopback, which also
affects remote build contexts and cache exports. Commands inside build
steps keep their own networking.

## Other fixes

- The control plane starts each rate-limit window on the first request for
  that key. Bursts around a wall-clock boundary now count toward the same
  limit.
- Guest step-report pacing tests now use the timestamp the guest uses to
  schedule requests. Firecracker cleanup tests wait for the VM they started
  to exit.

## Verification

The cache changes were exercised in an isolated arm64 Crew VM. Guest Docker,
both Buildx drivers, stock DinD and Foreman's systemd fixture pulled an
allowed image. A mirror refusal and an unknown registry produced zero direct
connections to a separately reachable recording origin. The dedicated M3
conformance run and live test-App end-to-end suite were unavailable for this release.

## Supply-chain review

No bumps.

The guest now declares its existing Telemetry dependency directly for the
step-report event. The lockfile still pins the same 1.4.2 artifact as 0.2.0.
