# Crew 0.2.2

The dashboard now shows fleet capacity, reservations, queue pressure and
24-hour job outcomes across all boxes. Boxes puts individual machines
ahead of their historical charts. Queue shows the oldest wait and how
many jobs are blocked or already have a runner. Usage breaks VM time
down into busy, idle, boot and teardown over the selected period.

## Registry cache

The box cache now passes upstream rate limits back to Docker as
`429 TOOMANYREQUESTS`, including `Retry-After` when supplied. It retries
once when the upstream asks for a short wait. This fixes pulls that
previously reported a missing manifest when the upstream was throttling.
Update the box cache to 0.2.2 to pick up the fix.

## Bare-metal enrollment

New Linux bare-metal boxes default to one disk. An OS disk of at least
128 GiB can hold Flatcar and a dedicated `/srv/crew` partition. A separate
data disk is still available. Add box asks for stable disk IDs and checks
for overlapping devices before installation.

Choose **Reprovision** when reinstalling an existing box whose Crew
data you want to keep. Adding it as a new box initializes the data
partition and removes the previous identity and data. Updating the
control plane does not repartition existing boxes.

## Upgrading

Back up the control-plane database before upgrading. One migration adds
two nullable columns to enrollment tokens for the OS disk and layout.
Existing tokens continue to use their previous separate-disk layout.

Starting with 0.2.2, the Deployment page estimates SQLite downtime
before you confirm the next upgrade. It measures the database, logs and
agent releases that the updater backs up. A 3 GiB backup gives an
estimate of 3–10 minutes offline, depending on disk speed and migration
time. PostgreSQL deployments get a reminder to take a provider snapshot.
