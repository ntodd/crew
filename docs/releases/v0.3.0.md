# Crew 0.3.0

Apple silicon workers now run as `mac-vz`, and `mac-vm` is retired. A new
box waits for an admin to accept what it reports before it gets jobs.
This release also hardens what a box can do to the control plane, fixes
rate limits behind Docker, and closes a long list of scheduler, agent and
network bugs found in a review of the fleet.

## Before you upgrade

- **`mac-vm` workers drain.** After the update, Crew stops placing jobs
  on `mac-vm` boxes and lets running jobs finish. Enroll each Mac again
  as `mac-vz` under a new name, check it, then revoke the old box.
  [Migrate a mac-vm worker to mac-vz](../setup/upgrading.md#migrate-a-mac-vm-worker-to-mac-vz)
  has the steps and the rollback.
- **New boxes need approval.** A box enrolled after the update shows
  **Needs approval** on its page and gets no jobs until someone clicks
  **Accept** on the capabilities it reported. Boxes already enrolled
  keep running.
- **Reinstalling means a new name.** A join token can no longer re-key a
  box that's already enrolled. To reinstall a box from scratch, revoke it
  and enroll it under a new name. **Reprovision** still keeps a box's
  identity and data.
- **Take the new `compose.yml`.** It adds
  `CREW_TRUSTED_PROXIES: ${CREW_TRUSTED_PROXIES-gateway}`. Until a
  Compose install takes it and recreates the container
  (`sudo docker compose up -d`), every client shares one rate limit for
  sign-in, enrollment and webhooks, as before.
- **Back up the database.** Three migrations add two indexes on
  operations, two nullable columns on join tokens (the uplink and extra
  blocked ranges) and one nullable column on boxes. None rewrites
  existing rows.

## Enrollment

- The Linux launcher, the macOS installer and the manual Ignition fetch
  ask for the join token on the terminal, with echo off, or read it from
  `--token-file`. Add box shows the token next to the command instead of
  inside it, so it stays out of shell history and process lists.
- Add box lists join tokens that haven't been used, with a fingerprint
  and a **Cancel** button. Expired tokens are pruned hourly, and their
  Tailscale keys go with them.
- Add box takes a Flatcar box's uplink interface and extra blocked IPv4
  ranges, and the box's firewall readiness reports missing ones.
  Existing boxes can install the settings as root during maintenance.
- `CREW_TRUSTED_PROXIES` takes CIDRs, or `gateway` for the container's
  default gateway. Crew believes the last `X-Forwarded-For` entry only
  from loopback or those ranges. A bad value stops the control plane at
  boot.

## What a box can send

- Integers from an agent are bounded: 64 bits everywhere, and 32 bits
  for log sequence numbers and the MiB and count fields stored in 32-bit
  columns. One VM's log stream crashing no longer takes the others down.
- A VM that goes busy without a job Crew can name keeps its share of the
  box until GitHub confirms its runner is gone, so a box can't hold more
  runners than it has room for.
- `image_not_ready` counts toward a box's quarantine, once per batch of
  placements, and takes that image off the box until it's prepared again.
- Agent crash reports keep only operational fields, and image downloads
  no longer carry the box's socket credentials.
- A freshly signed agent connects even when other clients behind the
  same address have used up the failure budget.

## Scheduling and GitHub

- Revoking an idle box queues its runners' removal. Runner deletes are
  coalesced across scheduler passes.
- Headerless secondary rate limits back off for a minute, doubling up to
  an hour. Runner registration honours the installation's write window.
- Missed-job checks rotate through open runs, and polling is budgeted by
  demand. Archived repositories drop out of demand, and `workflow_run`
  jobs are checked against the upstream repository.
- Webhook deliveries are pruned after seven days, finished operations
  expire with job retention, and webhook failures behind newer processed
  deliveries are recovered.
- A replacement agent channel takes ownership immediately, a VM server
  is restored before agent events reach it, VM exits are recorded before
  their network leases are released, and lost exits are recovered from
  the box's inventory.

## Boxes and VMs

- Different VMs start concurrently on one box.
- The agent watches storage every ten seconds. Under 5% free it stops
  the VM with the largest clone, and under 10% free in images it asks the
  control plane to remove the least recently used image that isn't a
  default, a fallback or in use.
- The guest service survives a job process running out of memory, so
  the runner reports the failed step and runs cleanup.
- A crash-looping Flatcar agent with nothing to roll back to retries
  after a minute. Flatcar boxes keep a root-owned version floor, so an
  update can't go backwards without a one-use authorization.
- Both Flatcar cache services get 65,536 file descriptors, and the
  cache's upstream pools are sized for the fetches it admits. Cache
  leaves are backdated an hour for clock skew.
- On `mac-vz`, the netstack resets a guest flow that has gone silent for
  two minutes after a retransmission, and logs what each stalled flow was
  waiting on. Reassembled UDP datagrams survive the relay, guest DNS is
  limited before the shared gateway, and the egress address is restored
  before VMs are accepted.
- The guest uplink accepts only new, established and related traffic.

## Dashboard

- Right-sizing loads its two reports separately and no longer runs a
  query per moved job. Medians average both middle durations, and
  missing job metrics stay out of them.
- Job charts update from incremental VM metrics. Log groups are bounded
  on the server and in the live viewer.
- Queue counts cancellations until they finish and leaves them out of
  starts. Job history matches when GitHub omits a job's name.
- Invalid run and job IDs return 404. The Oban dashboard rechecks admin
  access when it mounts and keeps only the admin's ID, login and role in
  its session.

Every PR passed CI on SQLite and Postgres, including the browser and
native jobs. The local e2e suite passed 32 tests and skipped 27 that need
hardware. The `mac-vz` changes were tested on an Apple M5 Max, including
a 20-minute download soak with no stalled flows. The dedicated M3
conformance run and the live GitHub test-App suite were not run for this
release.
